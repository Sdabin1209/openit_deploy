# 0004. E2E는 가짜 모델로 하고 전체 모드와 --only/--fast를 둔다

- 상태: 채택
- 날짜: 2026-10-28

## 맥락

GPU 서버는 따로 있고(D40) 모델 성능은 이 시스템 완성의 범위가 아니다(docs/E2E.md: '각 단계가 다음 단계의 입력을 만들고 순환이 닫히는지'만 본다, D38). 그래도 compose, 실제 PostgreSQL, 실제 게이트웨이·스케줄러·백업·복구·롤백은 실제로 돌려야 한다.

## 결정

model-serving은 model-runtime의 fake 백엔드(출력 고정, `MODEL_RUNTIME_ALLOW_FAKE=1`)와 시험용 어댑터·평가 보고서를 쓰고 이를 요약에 TEST-SUB로 표시한다. 인도 전 근거는 옵션 없는 전체 모드뿐이다. `--fast`는 단계 9의 스케줄러·백업·롤백을 생략하고, `--only <단계,...>`는 일부 단계만 돌리며 둘 다 결과를 정본(docs/E2E_RESULTS.md)에 기록하지 않거나 '전체 합격 아님'으로 표시한다.

## 왜 (따른 표준과 근거)

- 시험 대역은 이름에 test를 넣고 운영 설정으로 흘러들지 않게 한다(docs/E2E.md 머리말). 상태를 REAL/TEST-SUB/BLOCKED로 나눠 '돌린 검사가 모두 통과'를 '전체 합격'으로 오해하지 않게 한다.
- 개발 중 빠른 확인(약 2분 `--fast`, 단계 하나 `--only`)과 인도 전 전체 확인(약 8분)을 분리한다. 측정: 마지막 전체 실행의 구간별 소요(docs/E2E_RESULTS.md가 정본).
- 정적 일관성 점검 `check-all.sh`를 E2E 앞에 둔다: 영역 사이 어긋남을 8분 E2E 앞에서 수 초에 잡는다(2026-10-27 정적 일관성 우선 원칙).

## 검토한 대안과 버리는 이유

- 실제 GPU 모델로 E2E: 느리고 비결정적이며 GPU가 없는 환경에서 못 돈다. GPU 구멍은 docs/GPU_HOLE.md의 H1~H4로 분리했다.
- 단계 일부 생략을 기본으로: 인도 근거가 약해진다. 생략은 옵션으로만 두고 표시한다.

## 결과

- 가짜 모델은 모델 정확성·실제 지연을 보여 주지 않는다. 시간 불변식의 값(ADR 0003)은 이 E2E로 확정되지 않는다.

## 되돌리는 조건

GPU 환경이 상시 쓸 수 있게 되면 실제 모델 단계를 선택 모드로 추가한다(E2E_GPU 경로가 일부 있다).
