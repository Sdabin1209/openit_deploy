# 0005. TLS는 gateway에서 HTTPS 필수, 기본은 Caddy 내부 CA(`tls internal`)

- 상태: 채택(D88/U5), 구현 진행 중
- 날짜: 2026-10-28

## 맥락

게이트웨이가 지금까지 평문 HTTP로 기본 인증 암호, 기기 토큰, 환자 발화를 나른다(점검 B8, 심각도 H). 공개 도메인과 인증서는 병원 정보라 이 리포가 모른다. 키오스크와 직원 PC는 병원 내부망에 있다.

## 결정

gateway 리스너를 HTTPS로 하고 인증서는 Caddy 내부 CA(`tls internal`)가 발급하는 것을 기본으로 한다. 공인 인증서(ACME)는 설정으로 전환한다. 평문 포트는 HTTPS로 리다이렉트하되 컨테이너 헬스체크용 `/healthz`만 평문으로 남긴다. HSTS를 켠다. 서비스 사이(compose 내부 네트워크)는 평문을 유지하고 호스트 안에 한정됨을 문서에 적는다.

## 왜 (따른 표준과 근거)

- 표준 관행: 클라이언트가 닿는 경계에서 TLS를 종단하고 HSTS를 건다(D88/U5, head/docs/DECISIONS.md). 병원 도메인이 없어도 지금 암호화를 켤 수 있는 표준적 방법이 내부 CA다.
- 서비스 간 TLS를 하지 않는 이유: 같은 서버의 Docker 내부 네트워크이고 서비스·DB 네트워크를 internal로 분리했다(compose.yaml). 서비스마다 인증서를 배포·갱신하는 비용이 이득보다 크다고 판단했으나 **측정·위협 모델링한 근거는 없다**(근거 기록 없음: 판단).

## 검토한 대안과 버리는 이유

- **평문 유지 + 호스트 바인드 127.0.0.1**: 키오스크가 붙으려면 바인드를 열어야 해서 평문이 노출된다. 버린다.
- **공인 인증서(ACME) 기본**: 도메인과 80/443 공개가 필요한데 병원 내부망에서는 어려울 수 있다. 설정 전환으로 남긴다.
- **서비스 간 mTLS**: 위 이유로 지금은 하지 않는다. 재검토 조건에 둔다.

## 결과

- 내부 CA 루트 인증서를 키오스크와 직원 PC에 배포해야 한다(사람 일, runbook). 배포 전에는 브라우저 경고가 난다.
- E2E 클라이언트가 시험용 CA를 신뢰하도록 바뀐다(구현 상태는 docs/STATUS.md에 적는다).

## 되돌리는 조건

병원이 공인 인증서(ACME 또는 병원 CA 발급)를 쓰기로 하거나, 서비스가 다른 호스트로 나뉘면 서비스 간 TLS를 다시 검토한다.
