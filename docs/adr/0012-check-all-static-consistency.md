# 0012. 영역을 가로지르는 정적 일관성 점검(check-all)을 E2E 앞에 둔다

- 상태: 채택
- 날짜: 2026-10-28

## 맥락

영역 리포지토리가 열 개 남짓이고 버전표, 예시 키 순서, 완화 정책, 삭제된 이름, 박힌 계약 문자열처럼 **실행하지 않고 읽어서 알 수 있는 어긋남**이 E2E(전체 약 8분)에서야 발견되는 일이 있었다(그래서 '실행해야만 아는 것과 읽어서 알 수 있던 것을 구분해 정적 점검을 E2E 앞에 둔다'는 방침을 세웠다. 개별 사례의 목록은 이 ADR에 옮기지 않았다). 영역 시험은 각 영역이 자기 것만 본다.

## 결정

`scripts/check-all.sh`(`check_all.py`)가 형제 영역을 읽기 전용으로 읽어 규칙마다 PASS/FAIL/SKIP을 낸다. 규칙: 0 대상 열거, 1 버전표, 2 예시 키 순서, 3 완화 정책, 4 삭제된 이름, 5 박힌 계약 문자열, 6 설정 인라인 비밀, 7 compose 비밀, 8 시험 수집, 9 README 절, 10 E2E 통과 수는 정본에만, 11 compose 마운트 원본(규칙 번호는 스크립트 머리말이 정본). 출력은 `검증됨 N/M, 어긋남, 대상 아님(이유), 검증 안 함(이유)`이고 검증 대상에서 빠진 것을 통과로 세지 않는다. 모르는 대상(새 영역, 새 예시)은 FAIL이다. 허용·제외는 이유가 있는 파일에만 둔다(`check-all-allow.txt`, `check-all.exclude`). `e2e.sh`는 시작 전에 이것을 돌리고 FAIL이면 시작하지 않는다.

## 왜 (따른 표준과 근거)

- 실패는 빨리, 싸게: 정적 점검은 수 초이고 E2E는 약 8분이다. 시프트 레프트(검사를 앞당기는) 관행이다. 측정: 점검 전체가 4~6초(이 PC에서 2026-10-28 세 번 실행, 영역 시험 수집 포함).
- '통과'가 거짓이 되지 않게 한다: 대상이 0건이거나 환경이 없어 못 본 것은 SKIP/검증 안 함으로 따로 센다(워크스페이스 규칙: 확인하지 못한 것을 확인한 것처럼 쓰지 않는다).
- 정본이 하나여야 한다: E2E 통과 수 같은 사실은 한 곳(`docs/E2E_RESULTS.md`)에만 쓰고 복사본은 FAIL로 잡는다(규칙 10).

## 검토한 대안과 버리는 이유

- E2E에 맡긴다: 어긋남이 8분 뒤에, 그것도 증상으로만 나타난다.
- 영역마다 자기 점검: 영역 사이의 어긋남(버전표, 계약 문자열)은 한 영역이 볼 수 없다.
- 계약 패키지(boundary-contracts)의 시험만: 영역 코드·설정이 계약을 박아 쓰는 곳은 계약 패키지가 모른다.

## 결과

- 규칙은 정규식과 허용 목록에 의존해 거짓 양성이 날 수 있다(허용 목록 유지 비용). 규칙 8은 영역 시험을 **수집만 하고 실행하지는 않는다**(수집 오류 0건 확인). 영역 시험의 통과는 영역 몫이다.
- 형제 영역이 없는 환경(예: git worktree 안)에서는 `CHECK_ALL_WORKSPACE`를 줘야 한다.

## 되돌리는 조건

점검이 거짓 양성으로 개발을 막는 일이 잦아지면(허용 목록이 규칙 수만큼 늘면) 해당 규칙을 영역의 시험이나 계약 패키지의 시험으로 옮긴다.
