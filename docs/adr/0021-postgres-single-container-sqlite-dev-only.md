# 0021. PostgreSQL 한 컨테이너에 서비스별 데이터베이스 5개, SQLite는 개발·시험용

- 상태: 채택
- 날짜: 2026-10-28
- 관련: head/docs/DECISIONS.md D50(SQLite, D85(6)이 운영에 대해 대체), D85(6)

## 맥락

초기 구성은 영역마다 SQLite 파일(볼륨)이었다(D50, '기록 없음(초기 단순화)'). 사용자 지시(2026-10-27 결함 목록, D85(6))로 운영 저장소를 DB 서버(PostgreSQL)로 바꿨다. 남은 질문은 서버를 몇 개 두느냐와 SQLite를 어디까지 남기느냐다.

## 결정

- 운영은 공식 `postgres:16` 컨테이너 **하나**에 데이터베이스 5개(survey, qa, ops_log, ops_failure, gate)와 데이터베이스마다 최소 권한 계정 하나(자기 DB의 소유자, 슈퍼유저 아님, PUBLIC CONNECT 회수, 계정별 연결 상한)를 둔다. 서비스마다 자기 `db-*` 네트워크(internal)로 postgres에만 닿는다.
- SQLite는 영역의 개발·시험 기본으로만 남고 운영 compose에는 없다. 운영 저장소 경로에서 SQLite를 쓰지 않는다.

## 왜 (따른 표준과 근거)

- PostgreSQL 선택의 이유는 D85(6)·DECISIONS.md '결정 근거' 표가 정본이다: SQLite는 쓰기가 데이터베이스 전체에 직렬화되고(단일 writer) 네트워크 볼륨에서 잠금이 불안정해 서버와 잡이 함께 쓰는 구성에 맞지 않는다, 서비스별 DB와 최소 권한 계정을 둘 수 있다(감사 B12·C8), 서버에서 연결 상한 같은 정책을 강제할 수 있다, `pg_dump` 같은 검증된 백업 도구가 있다(C7). 여기서 다시 쓰지 않고 링크한다.
- **한 컨테이너인 이유**: 단일 서버 전제(ADR 0001-compose)에서 인스턴스 5개는 프로세스·메모리·백업·업그레이드 대상이 5배가 된다. 데이터 격리는 인스턴스가 아니라 데이터베이스·계정·네트워크로 얻는다(D85(6)의 판단과 같다). **메모리가 실제로 얼마나 더 드는지는 측정하지 않았다**: '부담이 크다'는 추정이다.
- **SQLite를 개발·시험에 남기는 이유**: 영역 독립 개발과 설치 없는 시험(D22)을 위해서다(D85(6)). '같은 적합성 시험을 두 저장소에 돌려 동작을 같게 유지한다'는 head의 주장이고, deploy는 영역 저장소의 시험을 읽지 않았으므로 **확인하지 못했다**.

## 검토한 대안과 버리는 이유

- **서비스마다 PostgreSQL 인스턴스**: 격리는 강하지만(메모리·연결·장애가 서비스별) 한 서버 위에서 운영·백업·업그레이드 대상이 5배다. 서버 한 대 전제에서 이득이 크지 않다고 판단해 버린다(측정 근거 없음).
- **한 데이터베이스에 스키마 5개**: 스키마 권한 분리는 가능하지만 데이터베이스 단위 백업·복구·CONNECT 회수·`pg_dump -U 소유 계정`의 단순함을 잃는다. 데이터베이스 분리가 같은 서버에서 더 강한 경계다.
- **MySQL/MariaDB, SQLite+복제**: D85(6)의 검토와 같다.

## 결과

- 얻는 것: 서비스별 권한 경계, 데이터베이스 단위 백업·복구, 서버 한 곳에서 로그·연결·인증 설정을 건다(ADR 0024).
- 감수하는 것: (1) **서버 하나가 전체의 단일 장애점**이고 한 서비스의 폭주가 같은 서버의 이웃을 느리게 할 수 있다(완화: 계정별 연결 상한, 컨테이너 자원 한도 — 값은 측정 안 함, ADR 0023). 자원은 데이터베이스별로 나뉘지 않는다. (2) **데이터베이스 사이 같은 시점의 백업은 불가능**하다(ADR 0020). (3) PostgreSQL 주 버전 업그레이드는 덤프·복원 절차가 필요하다. (4) 서비스 이미지가 PostgreSQL을 실제로 쓰는지는 E2E가 확인한다.

## 되돌리는 조건

- 한 서비스의 부하가 이웃을 반복해서 막는 것이 측정되면(H1) 그 데이터베이스만 별도 인스턴스로 분리한다.
- 단일 writer로 충분한 규모이고 백업을 파일 복사로 해도 된다고 사용자가 정하면(D85(6) '되돌리는 조건') SQLite로 돌아갈 수 있다.
