# 0063. 영역마다 자기 데이터베이스 컨테이너

- 상태: 채택(2026-11-04), 이전의 "공식 postgres:16 하나에 영역별 데이터베이스" 구성을 대체한다.
- 맥락: 서버 하나가 모든 영역의 데이터베이스를 들고 있으면 한 영역의 DB 계정·접속 문자열이 다른 영역의 컨테이너와 같은 서버·같은 슈퍼유저 암호에 묶인다. 구조 규칙 1(영역은 서로의 구조를 모른다)과 계약 CONVENTIONS 13절(데이터베이스는 영역의 컴포넌트)에 어긋난다. 영역 DB 가 서로 다른 서버에 놓일 수도 있어야 한다(RUNTIME R7.1).
- 결정: 영역마다 DB 컨테이너 하나(`survey-db`, `question-authoring-db`, `ops-feedback-db`, `release-gate-db`; 사람 인증 몫으로 `keycloak-db` 는 platform 으로 넘어갈 때까지 둔다). 각자 서버 인증서 컨테이너(`<DB>-cert`), 인증서 재읽기 컨테이너(`<DB>-reload`), 데이터·인증서 볼륨(`<DB>-data`, `<DB>-pgtls`), 슈퍼유저 암호 비밀(`pg-superuser-<영역>`), DB 망(`db-<영역>`)과 재읽기 망(`reload-<DB>`)을 가진다. 초기화는 `PG_INIT_ACCOUNTS` 로 자기 영역의 데이터베이스·계정만 만든다. DSN 의 호스트는 `<서비스>-db` 다.
- 왜(근거): (1) 한 영역의 DB 계정·암호가 다른 영역의 DB 컨테이너에 없다(`scripts/test-postgres.sh` 가 영역 DB 마다 로그인 계정이 자기 몫뿐임을 단언한다). (2) 이미지는 같은 공식 `postgres` 이미지(digest 잠금)이고 설정 서버 옵션도 같아 운영 부담이 늘지 않는다. (3) 영역이 DB 엔진·버전을 바꾸려 할 때 다른 영역을 건드리지 않는다.
- 검토한 대안: (a) 한 서버에 영역별 데이터베이스(현재) — 위 문제. (b) 영역마다 별도 서버(호스트) — 이 결정이 막지 않는다(배치 도구가 `<서비스>-db` 를 다른 서버에 놓을 수 있다, `ansible/inventory.multi.example.yml`). 컨테이너 분리는 그 전제다.
- 결과: 얻는 것 — 영역 경계가 DB 까지 맞는다. 감수하는 것 — 컨테이너 수가 늘고(각 DB 마다 cert·reload 포함 3개) 메모리 한도가 영역 DB 마다 따로 잡힌다(값은 측정하지 않았다, 시작값은 기존 `POSTGRES_*` 한도 그대로).
- 되돌리는 조건: 영역 수가 늘어 컨테이너 비용이 DB 격리 이득을 넘는다고 측정으로 보일 때.
- 백업: 백업 잡은 DB 를 가진 영역이 정한다(R10.1, 이미지 라벨 `io.openit.jobs` 의 `backup`). deploy 의 `scripts/pg-backup.sh` 는 영역 잡이 나오는 동안의 과도기 도구다.
