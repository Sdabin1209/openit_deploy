# 영역 브리프: deploy (배포)

> **계약 상태.** 이 리포지토리는 계약을 소비하거나 생산하지 않는다. 각 리포지토리가 게시한 이미지 digest만 입력으로 받는다. 일부 서비스(gateway, ingest-api, gate-service, authoring-app)의 최종 형태는 각 영역의 설계에 따라 정해지므로, 이 브리프의 서비스 목록은 시드다.

## 1. 목적과 범위

- 목적: 단일 서버에서 Docker Compose로 시스템을 합치고, 코드 축(이미지 digest)을 되돌릴 수 있게 한다.
- 하는 일: Compose 파일, 이미지 digest 잠금 파일, 네트워크·볼륨, 저장소별 데이터베이스와 계정, 헬스체크, 백업·복구 스크립트, 서버 밖 외부 감시 연동.
- 하지 않는 일: 서비스 코드 작성. 내용 축(릴리스 활성 포인터)의 되돌리기(게이트의 몫). 현장의 대체 절차(프로젝트 범위 밖).

## 2. 소유하는 것

- 소유 저장소: 없음. 인프라 정의와 운영 스크립트를 소유한다.
- 제공: 배포 절차(적용, 롤백), 백업·복구 절차.

## 3. 소비하는 것

- 소비: 각 리포지토리가 게시한 이미지 digest만. 다른 리포지토리의 코드는 가져오지 않는다.
- 상시 서비스 시드: gateway, orchestrator, inference(GPU), authoring-app, ingest-api, gate-service와 저장소. 합성 데이터·학습·평가·분석은 필요할 때만 도는 작업이고 운영 서버 밖에서 돌리기를 권한다.

## 3-1. 컨테이너 규칙(D22)

각 서비스 리포지토리가 자기 `Dockerfile`과 이미지 공통 모양(`shared/CLAUDE.root.md`의 컨테이너와 개발 절)을 책임진다. 이 리포지토리는 이미지를 빌드하지 않고 digest를 모아 합친다. 서버 안의 로컬 레지스트리를 쓰고, 각 리포지토리의 CI가 digest를 deploy에 제출한다(D24).

## 4. 상위 수용 기준

- 코드 축 롤백은 digest 잠금 파일을 이전 것으로 되돌리는 것으로 끝난다.
- 로더는 지원하지 않는 계약 버전의 묶음을 거부한다(코드와 내용이 계약 버전으로 만난다).
- 네트워크는 edge, serving, authoring, release, logs로 나뉜다. 외부 입구는 gateway 하나다(D11).
- 저장소마다 데이터베이스와 계정이 나뉘고, 다른 영역에는 읽기 전용 계정만 준다.
- 서버 전체 중단은 비보증으로 두되, 서버 밖의 외부 감시가 유지보수 담당에게 알린다(D10).

## 5. 비기능 요구

- 지연·자원: GPU를 inference에 할당. 허용 중단 시간과 복구 시점은 미정이며 백업 주기에 영향을 준다(O16).
- 보안·개인정보: 읽기 전용 계정 분리, 비밀 값은 리포지토리에 두지 않는다.

## 6. 건드리면 안 되는 경계

- 릴리스 활성 포인터를 직접 바꾸지 않는다.
- 이미지 안의 코드를 수정하지 않는다.

## 7. 이 영역에 해당하는 열린 결정

- O16 허용 중단 시간과 복구 시점: 사용자 결정. 정해질 때까지 백업 주기는 비워 둔다.
- O10 저장소의 실제 기술: 각 영역이 정하고 이 리포지토리가 맞춘다. 기본값은 저장소마다 DB·계정을 나눈 하나의 DB 인스턴스와 파일 볼륨.

## 8. 시드

Compose 파일, 이미지 digest 잠금, 네트워크·볼륨, 헬스체크, 백업·복구 스크립트.
