# CR-D13: 후보 수집기가 패키지 role을 구분하는지 (관찰 후 해소)

- 상태: 해소(재현되지 않음), 문서화 요청만 남김
- 보내는 곳: deploy -> head (영향: release-gate)

## 경과

E2E 단계 4의 수집기 run-once가 반복 시험으로 쌓인 레지스트리에서 접수 수가 문항 세트·패키지 조합 수보다 많아 보여(`submitted: 90`) 역할이 뒤바뀐 조합을 접수하는지 의심했다. 그래서 E2E에 관찰 행(4c: `lora_a`에 LORA_B 패키지를 넣은 조합의 판정이 있는지)을 넣었다. **깨끗한 레지스트리에서는 문항 세트 2개 버전 x LORA_A 1 x LORA_B 1 = 2건**(`submitted: 2`)이었고 뒤바뀐 조합의 판정도 없었다. 즉 role은 지켜진다. 이전 수는 여러 시험이 같은 레지스트리에 쌓인 결과였다.

## 요청

`watch`가 비어 있으면 `list_ids` 전체를 곱한다는 점과, 어떤 조합을 새로 접수하는지의 기준을 런북에 한 줄 적으면 좋다(운영에서 접수가 빨리 늘 수 있다).
