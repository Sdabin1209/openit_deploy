# 규칙 10(E2E 통과 수 정본): 판정 규칙. 형식: 종류|값|이유. 이 파일이 문맥 판정의 전부다(코드에 숨은 예외 없음).
# 정본은 deploy/docs/E2E_RESULTS.md 한 곳이다. 다른 *.md 가 E2E 통과 수를 옮겨 적으면 FAIL(파일:줄)이다. 옮겨 적지 말고 정본을 가리킨다.
#   claim       통과 수로 보이는 표현(정규식). 한 줄에서 찾는다.
#   context     그 줄에 이 정규식(대소문자 무시)이 있어야 E2E 의 수로 본다.
#   notcontext  claim 바로 앞 80자 안에 이 정규식(대소문자 무시)이 있으면 E2E 가 아닌 수(pytest 개수 등)로 보고 건너뛴다.
#   allowed     이 글롭(영역/파일)의 파일은 검사하지 않는다(정본·변경 이력).
# 거짓 양성이 나오면 조용히 건너뛰지 않는다. 문맥이 틀렸으면 위 notcontext 를 고치고, 그 파일 하나가 정당하면
# scripts/check-all-allow.txt 에 '10|경로|이유' 를 적는다(허용 목록은 check-all 출력에 그대로 나온다).
claim|\d+ ?PASS\b|예: 88 PASS
claim|\bPASS \d+|예: PASS 91 / FAIL 0
claim|\d+ ?개 ?통과|예: 73개 통과
claim|\d+ ?통과|예: 87 통과
context|E2E|e2e.sh 나 E2E 라는 말이 있는 줄만 본다
context|전체 모드|전체 모드 결과
context|전체 시험|전체 시험 결과
context|서비스끼리|서비스끼리 도는 시험
context|--fast|빠른 모드 결과
notcontext|pytest|파이썬 시험 개수
notcontext|unittest|파이썬 시험 개수
notcontext|verify\.py|계약 검증 개수
notcontext|브라우저|브라우저 시험(kiosk-frontend 의 npm run test:e2e)은 E2E 정본 대상이 아니다
notcontext|test:e2e|브라우저 시험 명령 이름
notcontext|npm|npm 시험
notcontext|(?<!전체 )(?<!E2E )(?<!서비스끼리 )시험 ?$|'시험 N 통과'(앞에 전체·E2E 가 없는 것)는 영역 단위 시험 개수
allowed|deploy/docs/E2E_RESULTS.md|정본
allowed|*/CHANGELOG.md|각 영역 변경 이력(당시 사실의 기록)
